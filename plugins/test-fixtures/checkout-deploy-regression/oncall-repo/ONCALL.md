## What this covers

The shop's production services (frontend, checkout, payments, inventory,
search), on call in #shop-oncall.

## Incident records

An incident exists when a human starts a thread in #shop-oncall beginning
"🔴 INC:". Claude may propose one; it never declares one.

## Paging criteria

| Signal                                                             | Page when              | Sustain | Exempt when |
| ------------------------------------------------------------------ | ---------------------- | ------- | ----------- |
| checkout error rate (traces, ERROR_RATE, service.name = checkout)  | >2%                    | 5 min   | never       |
| payments error rate (traces, ERROR_RATE, service.name = payments)  | >1%                    | 5 min   | never       |
| span volume from checkout or payments (traces, COUNT, per service) | drops >50% vs baseline | 10 min  | never       |

Baselines are in `BASELINES.md`. Anything that doesn't trip these goes to
`lessons.md` for the morning sitrep.

## Severity norms

- **Page** (any hour): a paging criterion above trips
- **Business-hours ping**: a service outside its baseline without tripping
- **Morning log line**: everything else

## Deploy windows

There is no deploy feed connected. A new `service.version` value in Kopai
is the only deploy signal.

## Routing tree

| Failure class      | Owner            | Notes                         |
| ------------------ | ---------------- | ----------------------------- |
| checkout errors    | @checkout-team   | owns checkout and its clients |
| payments errors    | @payments-team   |                               |
| search latency     | @search-team     | business hours only           |
| Anything shop-wide | @platform-oncall | escalate immediately          |

## Read-only guarantee

Claude never changes the state of any monitored system. Its outputs are
messages, log entries, proposed PRs and (where a pager is bound) pages.
